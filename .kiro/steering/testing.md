# Testing

## 受入基準ごとにテストを作る

- requirements.md の受入基準（Acceptance Criteria）1 つにつき、1 つ以上の自動テストを作る
- テストは JUnit 5 と Spring Boot Test で書き、`./mvnw test` で実行する
- テストを先に書き、失敗することを確かめてから実装する
- テストの期待値を変えるときは、変える理由を requirements.md か design.md に書く
- 画面（React）のテストは作らない。業務ルールは service と API のテストで確かめる

AI はテストを頼まれないと作らない。受入基準とテストを 1 対 1 で対応させておくと、どの受入基準が確かめられていないかが分かる。

## テスト用のデータベース

- テストは開発用とは別のデータベース（ecsite_test）を使う
- 現在の時刻は、時刻を固定した Clock に差し替えて確かめる

## 同時に更新される値

- 在庫数・予約の席・申請の状態のように、複数の利用者が同時に更新する値は、1 つのトランザクションの中で読み取りと更新を行う
- 後の更新が前の更新を上書きしないよう、楽観ロック（@Version）か、条件付きの UPDATE 文を使う
- 同時に更新する受入基準がある場合は、複数のスレッドから同時に呼ぶテストを作る

同時更新の取りこぼしは、1 人で画面を操作しても再現しないため。
